# ЗОНД: ECTS

Настольное приложение для проведения проверок и освидетельствований оборудования.
Инженер загружает CSV-шаблон проверки, приложение строит форму по группам полей,
сохраняет результаты и формирует PDF-протокол.

Стек: Python 3.13, [Flet](https://flet.dev) 0.86 (desktop), ReportLab (PDF).

---

## Возможности

* **Шаблоны из CSV** — 7 типов полей, группировка, обязательные поля, единицы измерения,
  подсказки и списки значений. Парсер терпим к «грязным» файлам: BOM, `cp1251`,
  разделители `,` `;` таб, пустые строки, незаполненные необязательные колонки.
* **Пошаговое заполнение** — переход по группам с валидацией обязательных полей
  и подсветкой ошибок.
* **Автосохранение черновика** — при переходе между шагами проверка сохраняется,
  её можно закрыть и продолжить позже.
* **История проверок** — список черновиков и завершённых проверок: продолжить,
  сформировать PDF, удалить.
* **Самодостаточный JSON** — вместе с результатами сохраняется снимок полей шаблона,
  поэтому отчёт и продолжение работы возможны без исходного CSV.
* **PDF-протокол** — метаданные, сводка, таблицы по группам, пометка незаполненных
  обязательных полей, подпись исполнителя, нумерация страниц. Кириллица через
  встроенный DejaVu Sans.
* **Миграция форматов** — файлы первой версии читаются и конвертируются на лету.

## Как пользоваться

1. **Загрузить шаблон проверки** — выберите CSV-файл (пример: `templates/sample.csv`).
2. **Проверить шаблон** — экран покажет число полей, групп и предупреждения разбора;
   при необходимости заполните объект и исполнителя для протокола.
3. **Заполнить форму** — данные сохраняются по шагам; обязательные поля отмечены `*`.
4. **Завершить** — проверка сохраняется автоматически, открывается экран итогов.
5. **Сформировать PDF** — кнопка на экране итогов или в истории проверок.

Продолжить незаконченную проверку можно двумя способами: «Открыть сохранённую проверку»
(выбор JSON-файла) или через «История проверок».

## Повторный выезд на тот же объект

Если по шаблону уже есть завершённые проверки, на экране подтверждения
появляется карточка **«Повторная проверка»**. Выберите нужную — приложение
подставит прошлые ответы, и править нужно только изменившееся.

Прежние замечания разбираются отдельным шагом перед формой: по каждому
отмечается состояние — **устранено**, **не устранено** или **не проверялось**,
пока все не разобраны, дальше не пустит. В протокол это попадает дважды: в
сводке строкой «Замечания прошлой проверки: устранено 1 из 2» и отдельной
таблицей, где закрытые замечания выделены зелёным, а оставшиеся красным.

Проверка выбирается вручную, а не подбирается по названию шаблона: один
шаблон используется на нескольких объектах, и автоматический подбор легко
подставил бы ответы с чужого.

Если шаблон между выездами поправили — поле переименовали или вариант списка
изменили, — несовместимое значение не подставится, но прежнее будет показано.
Поле, которого в новом шаблоне нет, пропускается, и об этом выводится
предупреждение: замечание не должно потеряться молча.

## Передать шаблон другому

На экране подтверждения шаблона есть кнопка отправки в шапке. Она передаёт
исходный CSV тем же системным меню, что и протоколы: почтой, в мессенджер или
в облако. Так пример из поставки забирают на компьютер и берут за основу
своего шаблона.

Работает и для своего файла, и для встроенного примера: файл внутри пакета
приложения системному меню тоже доступен.

## Откуда взять шаблон проверки

Три способа, от самого простого:

На стартовом экране — карточка **«Выбрать шаблон проверки»**: это одно
действие, поэтому и вход один. Источник выбирается на следующем шаге.

1. **Файл из памяти устройства.** Открывает системный диалог выбора файла.
   Файл должен уже лежать на устройстве: скачайте его из почты или облака,
   либо перекиньте по USB. На Android это обычно папка «Загрузки», на iOS —
   приложение «Файлы».
2. **Примеры.** Шесть готовых чек-листов внутри приложения — от КИП кранового
   узла до проверки серверной. Переносить на устройство ничего не нужно. Это
   образцы, чтобы посмотреть, как всё устроено, и взять за основу своего
   шаблона: на телефоне они доступны только для чтения.
3. **Отредактировать образец под себя.** Возьмите любой файл из `templates/`
   в репозитории, поправьте в Excel или LibreOffice (разделитель колонок —
   точка с запятой) и перенесите на устройство — дальше способ 2.

Формат файла описан в [docs/template.md](docs/template.md), нормативная основа
образцов — в [docs/normative-base.md](docs/normative-base.md).

Та же инструкция есть в самом приложении: ссылка **«Справка»** на стартовом
экране.

## Где искать отчёты

**Готовые протоколы лежат отдельно от служебных данных** — там, где
пользователь ищет файлы сам:

| Платформа | Протоколы PDF | Данные проверок |
|---|---|---|
| Android | общая папка `Документы/ЗОНД` | каталог приложения |
| iOS | каталог документов приложения (виден в «Файлах») | там же |
| Настольные | `reports/pdf/` в корне проекта | `reports/` |

Каталог `incoming/` — служебный: туда попадают копии выбранных из памяти
файлов, потому что после выбора система путь к исходному файлу не отдаёт.
Копия нужна, чтобы отправить шаблон другому человеку. Хранятся последние
20 копий, более старые удаляются автоматически.

Служебные данные — подкаталоги каталога `reports/`:

```
reports/
├── drafts/        # незавершённые проверки: сюда попадает каждое сохранение по шагам
├── inspections/   # завершённые проверки: <дата>_<шаблон>_<id>.json
├── pdf/           # протоколы, если общая папка недоступна
└── incoming/      # файлы, выбранные из памяти устройства
```

На Android протоколы попадают в общую папку «Документы», поэтому их видно в
файловом менеджере и по USB. Дополнительно на экране итогов есть кнопка
**«Поделиться»**: она открывает системное меню с почтой, мессенджером,
облаком и печатью. Куда именно сохраняются протоколы, показано на стартовом
экране и в справке.

Полный путь на экране итогов показывается и для JSON, и для PDF — оттуда его
можно скопировать. Забрать все отчёты разом по USB:

```bash
adb pull /storage/emulated/0/Android/data/ru.pyconstrictor.zond/files/reports/ ./reports
```

## Мобильное приложение

Приложение работает на Android и iOS: данные сохраняются в каталог документов
приложения, выбранные файлы читаются через содержимое, а готовый протокол
отправляется через системное меню «Поделиться». На стартовом экране есть кнопка
**«Загрузить образец»** — встроенные шаблоны не нужно переносить на телефон.

Сборка:

```bash
flet build apk                  # Android, установка вручную
flet build aab                  # Google Play
flet build ipa --ios-team-id ID # iOS
```

Для сборки нужны Flutter SDK, Android SDK и JDK 17 (для iOS — macOS и Xcode).
Пошаговая инструкция, чек-лист проверки на устройстве и разбор возможных
сложностей — в [docs/mobile.md](docs/mobile.md).

Запись выполняется атомарно (временный файл + `os.replace`), поэтому прерывание

В каталоге `templates/` шесть файлов:

| Файл | Назначение | Полей | Групп |
|---|---|---|---|
| `kip_kranovyy_uzel_mg.csv` | КИП кранового узла магистрального газопровода | 152 | 10 |
| `elektroustanovki.csv` | Электроустановки | 123 | 11 |
| `tehnicheskie_sredstva_ohrany.csv` | Технические средства охраны | 113 | 10 |

**КИП кранового узла** — датчики и преобразователи, манометры, импульсные и

**Электроустановки** — документация и организация эксплуатации, заземление и
защитные меры, кабельные линии, щиты, электродвигатели, освещение,
молниезащита, взрывозащищённое электрооборудование, безопасность работ.

**Технические средства охраны** — инженерно-техническая укреплённость,
охранная и тревожная сигнализация, охранное телевидение, контроль и управление
доступом, периметровые средства обнаружения, электропитание и линии связи.

**УАЗ Патриот** — документы и допуск к эксплуатации, предрейсовый контроль,
тормозная система, рулевое управление, шины и колёса, светотехника и
обзорность, двигатель, трансмиссия и полный привод, подвеска и кузов,
электрооборудование и эксплуатационные жидкости.

**Стационарное подъёмное сооружение** — организация эксплуатации и
документация, паспорт и маркировка, металлоконструкции, тормоза и механизмы,
канаты, цепи и крюки, грузозахватные приспособления и тара, приборы
безопасности, управление и связь, крановый путь и противоугонные устройства,
электробезопасность, осмотры и освидетельствования.

**Серверное помещение и сервер** — документация и организация, физический
доступ в помещение, пожарная безопасность и пожаротушение, электропитание и
бесперебойность, микроклимат и кабельное хозяйство, учётные записи и пароли,
обновления и защита от вредоносного кода, резервное копирование и
журналирование.

Нормативная основа каждого шаблона разобрана в
[docs/normative-base.md](docs/normative-base.md): что проверено по открытым
источникам, что привлекается по общеотраслевой практике и что требует сверки.

Примеры заполненных протоколов: [КИП](docs/sample-protocol-kip.pdf),
[электроустановки](docs/sample-protocol-elektroustanovki.pdf),
[ТСО](docs/sample-protocol-tso.pdf). Пересобрать все примеры разом:

```bash
python tools/make_demo_report.py
```

Ответы в протоколе выделяются цветом: соответствия зелёным, несоответствия
красным, а в начале отчёта выводится их сводка и перечень выявленных
несоответствий.

## Формат шаблона CSV

Полное описание — [docs/template.md](docs/template.md). Кратко:

| Колонка | Обяз. | Назначение |
|---|---|---|
| `order` | нет | порядок поля (число); при отсутствии — порядок строк |
| `name` | **да** | машинное имя поля, уникальное |
| `label` | **да** | подпись в форме |
| `type` | **да** | `text`, `number`, `date`, `time`, `dropdown`, `checkbox`, `textarea` |
| `group` | нет | группа (шаг формы), по умолчанию «Общие сведения» |
| `required` | нет | `true` / `да` / `1` |
| `options` | для `dropdown` | варианты через `;`, `|`, таб или запятую |
| `placeholder` | нет | подсказка внутри поля |
| `description` | нет | пояснение под полем |
| `unit` | нет | единица измерения |

## Структура проекта

```
zond/
├── ects.py                  # точка входа
├── app/                     # ZondApp (композиция), ZondState, навигатор
├── models/                  # Field, Template, Inspection, InspectionItem
├── services/                # CSV-парсер, хранилище JSON, генератор PDF, ошибки
├── ui/
│   ├── components/          # кнопки, карточки, заголовки, прогресс, диалоги
│   ├── screens/             # upload, check, inspection, finish, history
│   └── widgets/             # FieldControl — построение полей формы
└── utils/                   # настройка логирования
```

Слой `services` не зависит от Flet; `models` — чистые dataclass-ы; экраны получают
всё необходимое через объект приложения (`Screen(app)`).

Тесты не требуют графического окружения: логика экранов проверяется на лёгкой
